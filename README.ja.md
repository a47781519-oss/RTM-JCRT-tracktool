# track-tool

**RealTrainMod (RTM) 向けの敷設支援 MOD** — マーカーを一つずつ手で置く代わりに、本物の鉄道線形（緩和曲線 + 円曲線 + 緩和曲線、外軌カント、縦曲線）でレールを敷設します。

**言語:** [中文](README.md) · [English](README.en.md) · **日本語**

| | |
|---|---|
| Minecraft | 1.12.2 |
| ローダー | Forge 14.23.5（コンパイルは 2768、動作確認は 2847 / 2860） |
| 前提 | **RealTrainMod 2.4.24** + **NGTLib 2.4.21** |
| modid / バージョン | `tracktool` / 0.1.0 |
| Java | 8 |

> **クライアントとサーバーの両方**に入れ、**同一の jar** を使ってください。パラメータパケットにはバージョンが入っており、不一致だとサーバーが赤字で拒否し、双方のバージョンを表示します。

---

## 何を解決するのか

RTM 標準の敷設方法は、マーカーを 2 つ置いてその間を **ベジェ曲線**で結ぶもので、アンカーは「ハーフブロック格子 x 8 方向」に量子化されます。直線や大半径の曲線なら十分ですが、鉄道規格の線形を作ろうとすると 3 つの問題が出ます。

1. **緩和曲線がない** — 曲率が 0 から 1/R へ急変し、車両の挙動が不自然になる
2. **継ぎ目で折れ角が出る** — 区間ごとにベジェを当てはめるため、アンカーの量子化誤差で隣接区間の接線が合わない
3. **カントのすり付けがない** — カントが無いか、継ぎ目で急変する

track-tool は**線形を自前の解析幾何で完全に決定**し、RTM には描画と走行だけを任せます。

```
ユーザー参数 --> plan（純粋な数学）--> ExactLine（NGTLib の ILine を実装）
                                        |
                                        +--> RailMapBasic 内部の 2 つの ILine を
                                             リフレクションで差し替え
                                             （オブジェクト型は RailMapBasic のまま
                                              なので描画と車両はそのまま動く）
```

結果として、量子化ゼロ・継ぎ目の接線連続・設計どおりのカントすり付けを、RTM 側に一切手を入れずに実現します。

## 使い方

### 0. はじめに

1. クライアントとサーバーに**同一の jar**（`mods/`）を入れる（バージョン一致が必須）
2. **RealTrainMod 2.4.24** + **NGTLib 2.4.21** を用意する
3. サーバーでは **OP**（権限レベル 2）が必要。シングルプレイなら不要

> **最初にワールドをバックアップしてください。** 敷設はブロックを変更し、RTM はバラストも整形します。

### 1. 杖を入手

クリエイティブの物品欄 → タブ **「RTM Track Laying」** → **Track Staff**（`tracktool:rail_staff`）を取ります。

### 2. 端点を選ぶ

**既存レールの端に右クリック**します。レールの中ほどをクリックすると「レール端を選んでください」と出ます（意図的な仕様）。同じ端をもう一度右クリック、`/tracktool cancel`、または **ESC** で解除できます。

### 3. パラメータパネルを開く

**G** キー（変更可）または `/tracktool gui`。パネルは画面右 1/3 に半透明で出て、3 つのモード（**直線 / 曲線 / 接続**）、パラメータ（半径、交角、カント、緩和曲線長または自動、上げ高、縦曲線半径、平行線の本数と間隔）、プレビュー表示、確認 / 元に戻す / 戻る / キャンセルのボタンがあります。

### 4. 最初の曲線を敷く

| パラメータ | 推奨値 | 備考 |
|---|---|---|
| モード | 曲線 | |
| 半径 | 300 | m |
| 交角 | 45 | 度（90 にすると分かりやすい） |
| 緩和曲線 | 自動 | 半径に応じて GB 50090 の表から取得 |
| カント | 60 | 0 でも可 |
| 上げ高 / 縦曲線 | 0 / 既定 | 最初は触らない |

確認するとチャットに `敷設完了: N 個のレールコア、M ブロック` と出ます。歩いて確認すると、緩和曲線で曲率が漸増し、円曲線で一定になり、継ぎ目に折れ角がありません。外軌は高くなり、すり付けは緩和曲線内で完了します。

### 5. 元に戻す

パネルの**元に戻す**、または `/tracktool undo`（既定 8 段、`maxUndo` で変更）。

## 応用

- **接続モード** — 2 つのレール端を選ぶと「直線-緩和-円-緩和-直線」を解いて**正確に閉合**します（終点誤差 0.000 m、向き誤差 0.000 度）。両端が平行で横にずれている場合（S 字）はソルバが無く、誤った線形を敷かずにエラーを返します
- **複線・多条線** — 左右の本数と間隔を指定すると**正確な等距線**を敷きます（緩和曲線の等距線は緩和曲線ではないため `ds' = (1 - kd) ds` で里程を逆算し、直線近似はしません）
- **カント** — 緩和曲線で線形にすり付け、円曲線で一定。**上限 10 度（約 260 mm）**。それ以上では RTM がバラスト上面を傾けすぎて、バラストが壁になりレールが埋もれます
- **縦曲線** — 上げ高 + 縦曲線半径で勾配変化を滑らかにします
- **長い路線** — 複数 tick に分けて敷設（`segmentsPerTick` / `blocksPerTick`）。未読み込みチャンクをまたぐ場合は `forceLoadChunks` を true のままに
- **1 路線を 1 コアで** — `/tracktool exact seg 0` で 1 コア、`/tracktool exact seg 30` で 30 m ごと、`/tracktool exact false` で RTM 標準の分割経路に戻して A/B 比較

## おかしいときの確認順

| 症状 | まず確認 |
|---|---|
| **車両が動かない / 線路を見つけない** | `/tracktool test railcheck`（車両と同じ探索経路をたどり、台座 / コア / RailMap の 3 つのカウントを表示）。`fix` を付けるとその場で補修 |
| **継ぎ目が揃って見えない** | `/tracktool test joints`（描画高さの差と区間内カントの潰れを報告） |
| **プレビューが出ない / 描画がおかしい** | `/tracktool test clientcheck`（コアごとに線形の出所、長さ、レールと自分のバラストのずれ、バラスト上面高さを表示） |
| **確認しても何も起きない** | `/tracktool status` で選択とパラメータを確認。サーバーにも同じ jar が入っているか確認 |
| **サーバーがバージョン不一致で拒否** | 両側を同じ jar にする |
| **計算が正しいか確かめたい** | `/tracktool exact selftest`（敷設せずに長さ / 端点の向き / カントを検算） |

診断の出力はチャットと `latest.log` の両方に出ます。

## コマンド

```
/tracktool <confirm|back|undo|cancel|status|mode|param|plan|help>
```

権限レベル 2。`mode` は `straight|curve|connect`、`param <名前> <値>` はパネルの各入力欄に対応します。

診断コマンド: `/tracktool test joints [半径]`、`/tracktool test clientcheck`、`/tracktool test railcheck [n] [fix]`、`/tracktool test cell`、`/tracktool exact [true|false]`、`/tracktool exact seg <メートル>`、`/tracktool exact selftest`。

## 設定

`config/tracktool.cfg`:

| キー | 既定 | 内容 |
|---|---|---|
| `selectDistance` | 16 | 杖のレイ距離（ブロック） |
| `segmentLength` | 20.0 | 1 つの RTM レールコアが受け持つ線路長（m） |
| `blocksPerTick` | 3000 | 敷設時に 1 tick で書き込む最大ブロック数 |
| `forceLoadChunks` | true | 長い路線で通過チャンクを強制読み込み |
| `previewEnabled` | true | 青い半透明プレビューを描画 |
| `maxUndo` | 8 | プレイヤーごとに保持する元に戻す段数 |
| `guiBackdrop` / `guiBackdropAlpha` | true / 140 | パネルの背景板と不透明度 |

## コントリビュータ向けの厳守事項

苦い経験から学んだものです。コードを変える前に必ず読んでください。

1. **RailMapBasic をサブクラスに置き換えないこと。** RTM の描画経路は railmap の実装に強い前提を置いており、サブクラスにすると線路が**まったく描画されません**。差し替えてよいのは内部の 2 つの `ILine`（`lineHorizontal` / `lineVertical`）だけです
2. **`RailPosition.scriptName` を設定しないこと。** `createRailMap()` が `RailMapCustom` を作ろうとし、スクリプトエンジンは null なので `Script exec error` になります
3. **共通クラスからクライアント専用型を参照しないこと。** 到達しないコードでも、クラス検証時に JVM がその型を読み込もうとし、専用サーバーでは `NoClassDefFoundError` でクラスごと使えなくなります。クライアント側は `com.tracktool.client` に分離し、共通側からはリフレクションで呼びます
4. **`world.loadedTileEntityList` を回す前にスナップショットを取ること。** ループ内で `world.getTileEntity(...)` を呼ぶと、クライアントがその場で TE を生成してリストに追加し、`ConcurrentModificationException` になります
5. **レールコアのブロックが置かれたら、必ず `railPositions` を書くこと。** RTM の `writeRailData` は `railPositions[0]` を null チェックなしで読むため、データの無いコアが残るとサーバーがパケット送出時に NPE を起こし、セーブやサーバーが落ちます。配置と元に戻すの両経路に `try/finally` の保険を
6. **単位とフィールド順はバイトコードで確認してから書くこと。** 例えば `RailMap.getRailPos` は `[Z, X]` を返し（`[X, Z]` ではない）、`ILine.getSlope` は**ラジアン角**を返し、`NGTMath.sin` は**度**を取ります
7. **パケットのフィールドを変えたら `TrackSpec.VERSION` を +1 すること。** 同じバージョン番号でレイアウトだけ違うと、パラメータを静かに読み違えます

### カントを 10 度で制限する理由

RTM の `TileEntityLargeRailBase.getBlockHeights` は、バラスト上面をカント平面に沿って傾けます。

```
各角の高さ = レール面の高さ - y + sin(カント) x (中心線からの距離)   // クランプ無し
```

カントが大きいと外縁が大きく持ち上がり（20 度では 1 ブロック以上）、バラストが斜めの壁になってレールが埋もれます。10 度は約 260 mm で、既に GB 50090 の上限 150 mm の約 2 倍です。それ以上では RTM は妥当な道床を描けません。

## 既知の制限

- 接続モードに **S 字**のソルバがありません。両端が平行で横にずれている場合は接続できません（誤って敷かず、明示的にエラーを返します）
- カントの上限は 10 度（理由は上記）
- 解析幾何の経路は 1 本あたり **4000 m** まで。それを超えると RTM 標準の分割経路に戻ります
- サンプル点表は 1024 点が上限です。線路が長いほど間隔が粗くなります（約 `長さ / 1023` m）。R = 300 m のときの弦誤差は約 2 km で 1.6 mm、4 km で 6.3 mm と、モデルで見える尺度よりはるかに小さい値です。さらに延ばす前に継ぎ目を確認してください
- `core/` の ASM 骨組みは未使用

## 中国の鉄道規格（GB 50090）について

本 MOD は中国の国家規格 **GB 50090**「鉄道線路設計規範」（Code for Design of Railway Line、GB 50090-2006）を
参考に開発しています。これは**依存関係ではありません** — RealTrainMod はこれらの値を検証しません — が、
既定値、パラメータ欄の横に表示される参照表、安全上の上限はここから来ています。すべての値はパネルで上書きできます。

### どこを参考にしているか

| 概念（中国語） | 本 MOD での扱い | GB 50090 の出典 |
|---|---|---|
| **緩和曲線長**「缓和曲线长度」 | 設計速度と半径ごとの推奨値。一般 / 困難の「最小」表も別途 | 表 3.1.5-1（推奨、160/140/120 km/h）、表 3.1.5-2（最小、全速度） |
| **最小曲線半径**「最小曲线半径」 | 設計速度ごとの参照値 | 表 3.1.2 |
| **均衡カント**「均衡超高」 | `h = 11.8 x V^2 / R` mm（`V` は km/h、`R` は m）。レール中心間 1500 mm を基準とし、**上限 150 mm**、5 mm 単位に量子化 | 同規格のカント式から導出 |
| **カント不足量**「欠超高」 | 一般 70 mm / 困難 90 mm。カント値の提案に使用 | カント不足量の規定 |
| **カント勾配**「超高顺坡率」 | 推奨 1 パーミル — すり付けを緩和曲線内で行うのはこのため | カントすり付けの規定 |
| **縦曲線**「竖曲线」 | 160 km/h で勾配変化が 1 パーミルを超えるとき `Rv = 15000 m`、160 km/h 未満で 3 パーミル超のとき `Rv = 10000 m`、長さ `L = Rv x |di| / 1000` | 縦曲線の規定 |
| **設計速度**「设计速度」 | 160 / 140 / 120 / 100 / 80 km/h | 同規格の速度系列 |

緩和曲線長の自動計算に使う既定の設計速度は **160 km/h**（中国の幹線旅客線で一般的な値）です。標準軌間は 1435 mm です。

### 規格より大きいカントを許す理由

GB 50090 のカント上限は **150 mm**（1500 mm 基準で約 5.7 度）です。本 MOD は **10 度（約 260 mm）**まで受け付けます。
これはゲームだからで、10 度を大きく超えると RTM がバラスト上面を傾けすぎて道床が斜めの壁になり、
レールが埋もれてしまいます。つまり 10 度は**描画上の限界**であり、工学上の限界ではありません。
実物らしく見せたい場合は規格どおり 150 mm 以下に留めてください。

### 用語集

- **缓和曲线 / 緩和曲線（イージメント）** — 直線と円曲線の間に置くクロソイド。曲率が線形に変化します
- **圆曲线 / 円曲線** — 曲率が一定の、曲線本体の部分
- **超高 / カント** — 遠心力の一部を重力で釣り合わせるため、外軌を高くすること
- **超高顺坡 / カント勾配** — その高さを徐々に導入する割合。緩和曲線内で完了させます
- **竖曲线 / 縦曲線** — 勾配が変化する箇所を滑らかにつなぐ曲線
- **坡度 / 勾配** — 縦断勾配。通常はパーミルで表します
- **轨距 / 軌間** — レール中心間の距離。1435 mm が標準軌
- **设计速度 / 設計速度** — 線形を決定する基準となる速度

> 要するに、GB 50090 は**鉄道として妥当な既定値**を提供するものです。幾何エンジン自体は速度に依存せず、
> 与えられた数値に従って線形を作るだけです。
